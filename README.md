# Домашнее задание № 1 · Кварталы и метрики города: от данных к дашборду

**Курс «Технологии искусственного интеллекта в урбанистике»**
Исследование территории города **Тюмень** на основе BlocksNet.

Готовый результат — одна автономная страница:
[`examples/data_tyumen/dashboard_refined.html`](examples/data_tyumen/dashboard_refined.html).

---

## Цель

Подготовить кварталы Тюмени, рассчитать показатели BlocksNet и собрать одну
HTML-страницу с интерактивной картой, графиками, таблицами и выводами.
Расчёты выполняются в Jupyter-ноутбуке, страница собирается отдельным
Python-скриптом **из готовых сохранённых файлов** — без скачивания данных и
без повторного расчёта показателей.

## Что получилось

| | |
|---|---|
| Кварталов | **12 805** (из 11 625 до дополнительного разделения крупных) |
| Площадь кварталов | 449,76 км², покрытие территории 99,95 %, пересечений нет |
| Население | **980 707 чел.** — модельная оценка по жилой площади зданий |
| Школы | 70 (из 82 объектов OSM после удаления дубликатов), модельная вместимость 250 мест |
| Время пешего пути | матрица 12 805 × 12 805, минуты; среднее по кварталу — 175,2 мин |
| Застройка | 7 278 кварталов с зданиями (FSI > 0), 5 527 без застройки |
| Обеспеченность школами | средняя 0,073 (в пределах 15 минут), применима к 3 213 кварталам с населением |

## Методика

1. **Источник данных** — локальный архив OpenStreetMap (Geofabrik, Уральский
   федеральный округ, ODbL 1.0), извлечение без обращения к Overpass.
2. **Кварталы** — разбиение по BlocksNet 1.0.0a9 с последующим дополнительным
   разделением кварталов площадью более 1 км² по жилой застройке. Пустые
   крупные полигоны без зданий искусственно не дробились.
3. **Пешеходный граф** — один готовый граф (69 733 узла, 194 308 рёбер);
   время в пути в минутах, интермодальные варианты не используются.
4. **Матрица доступности** — 12 805 × 12 805, считалась порциями по 25 строк;
   полная матрица не встраивается в страницу, используется её производная
   `area_accessibility`.
5. **Показатели** — население, площади зданий, землепользование, обеспеченность
   школами (оба показателя), плотностные индексы (FSI, GSI, MXI, L, OSR),
   морфотипы Spacematrix и Strelka.
6. **Страница** — генератор `examples/tyumen_dashboard_refined.py` читает
   готовые файлы из `examples/data_tyumen/refined/` и собирает один HTML:
   интерактивная карта Leaflet с переключателем показателей (карта, легенда и
   график обновляются одновременно), таблицы, графики, выводы и ограничения.
7. **Проверки** — автоматические проверки геометрии, данных и матрицы
   (`quality_report.json`, `blocks_quality.json`).

## Краткие выводы

- Квартальная структура покрывает 99,95 % территории города без пересечений и
  выходов за границу; уточнение нарезки изменило число кварталов с 11 625 до 12 805.
- Население распределено крайне неравномерно: 9 592 квартала (75 %) без
  населения, топ-10 кварталов концентрируют заметную долю жителей.
- Школьная сеть в модели: 70 школ, 17 500 мест, потребность по нормативу
  120 мест на 1000 жителей — 119 231 место, покрыто в пределах 15 минут
  16 835 мест, дефицит 102 396 мест. **Это модельная оценка**: реальная
  вместимость школ в OSM отсутствует.
- Обеспеченность применима только к кварталам с населением (3 213 из 12 805);
  в остальных она не определена и остаётся белой на карте.
- Связность территории неравномерна: время пешего пути от 138,2 до 385,9 мин,
  медиана 166,6 мин.
- Типы застройки по Spacematrix и Strelka устойчиво выделяют микрорайоны
  советского и современного высокоэтажного профиля.

## Ограничения

- Население — **модельная оценка** (распределение по жилой площади), а не
  официальная статистика.
- Вместимость 250 мест на школу — **модельное допущение**; суммарные
  17 500 мест не являются подтверждённой вместимостью школ Тюмени.
- Полная матрица доступности (≈ 1,4 ГБ) не публикуется в репозитории и
  передаётся отдельно по ссылке; на странице показаны её производные.
- Геометрия кварталов на карте упрощена; классификация цветом — квантильная,
  данные не изменяются.
- Показатели относительной доступности, связности, центральности, вакантных
  территорий и услуг кроме школ **не рассчитывались** и не выдумываются
  (перечень — в разделе «Соответствие исходному заданию» на странице).

## План работы

1. Окружение: `.venv` + `blocksnet[ipynb,torch]==1.0.0a9`.
2. Граница территории (relation R2049854) → `boundaries.geojson`.
3. Локальный PBF → дороги, железные дороги, вода, функциональные зоны, здания, школы.
4. Кварталы BlocksNet → дополнительное разделение крупных кварталов.
5. Пешеходный граф и матрица времени в пути (порциями, с возобновлением).
6. Здания и население; школы и вместимость.
7. Землепользование, плотностные показатели, морфотипы Spacematrix и Strelka.
8. Доступность территории, обеспеченность школами, проверки качества.
9. Генератор страницы: интерактивная карта, графики, таблицы, выводы.
10. Сверка результатов с исходным заданием и проверка страницы в браузере.

## Повторный запуск (Windows, PowerShell)

```powershell
# 1. Активировать окружение
Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
(& ".\.venv-blocksnet\Scripts\Activate.ps1")

# 2. Зависимости (устанавливаются один раз)
pip install "blocksnet[ipynb,torch]==1.0.0.a9" -q

# 3. Пересобрать страницу из готовых результатов
python .\examples\tyumen_dashboard_refined.py

# 4. Открыть страницу
Start-Process ".\examples\data_tyumen\dashboard_refined.html"
```

Ноутбук с расчётами запускается отдельно: открыть
`examples/tyumen_pipeline_refined.ipynb` в VS Code, выбрать ядро
`.venv-blocksnet` и выполнить ячейки по порядку (`Kernel → Restart Kernel and
Run All Cells`). Матрица доступности считается порциями и переживает остановку.

Генератор страницы **не обращается к сети и не пересчитывает показатели**:
он читает готовые файлы из `examples/data_tyumen/refined/`.
