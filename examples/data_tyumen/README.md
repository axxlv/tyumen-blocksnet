# Тюмень: две независимые версии исследования

В этой папке сохранены две версии данных. Они не должны смешиваться.

## `original/` — сохранённый первоначальный расчёт

- Ноутбук: `examples/tyumen_pipeline_original.ipynb`
- Данные: `examples/data_tyumen/original/`
- Это копия первоначального прогона `examples/data_tyumen_pbf/full/` без изменения содержимого.
- Дополнительно рядом с `tyumen_full.osm.pbf` лежит байт-в-байт копия
  `tyumen_original.osm.pbf`; ноутбук читает именно её.
- В `original/` сохранены исходные кварталы, матрица, здания, школы, карты и
  итоговая таблица. Папку не нужно перезаписывать. В ноутбуке включён
  `ORIGINAL_READ_ONLY = True`: существующие файлы не перезаписываются.
- В исходном прогоне: 10 639 кварталов, 980 710 человек модельного населения,
  82 школьных объекта и 20 500 модельных мест. Школы не дедуплицированы,
  `capacity` в OSM отсутствует.

## `refined/` — исправленный расчёт

- Ноутбук: `examples/tyumen_pipeline_refined.ipynb`
- Данные: `examples/data_tyumen/refined/`
- Ноутбук уже запущен; в папке лежат итоговые кварталы, матрица, здания,
  школы, метрики, сравнение и карты.
- Входные данные, которые переиспользуются:
  - `tyumen_refined.osm.pbf` — локальный PBF;
  - `boundaries.geojson`;
  - `functional_zones.geojson`;
  - `graph.pkl` — пешеходный граф;
  - `railways.geojson`, `water.geojson`;
  - `buildings_raw.geojson` — исходные здания OSM;
  - `schools_raw.geojson` — исходные школьные объекты OSM (82 шт.).
- Ноутбук сам не скачивает данные и не использует Overpass API.
- Дополнительное разделение крупных кварталов включается параметром
  `SPLIT_LARGE_BLOCKS = True`; порог по умолчанию — `SPLIT_MAX_AREA_KM2 = 1.0`.
- В окружении нет пакета `hdbscan`, поэтому ноутбук автоматически использует
  `sklearn.cluster.HDBSCAN` для кластеризации зданий внутри `split_blocks`.
  Остальные шаги `split_blocks` остаются штатными.
- Матрица доступности считается порциями в
  `refined/accessibility_matrix_parts/`; при сбое расчёт продолжается с
  сохранённых порций.
- Крупные пустые полигоны без зданий не дробятся искусственно: у них нет
  внутренней структуры, которую можно восстановить по зданиям.

## Что важно не перепутать

1. `original/` — только чтение, это baseline.
2. `refined/` — рабочая папка нового расчёта; её производные файлы можно
   пересоздавать.
3. `examples/data_tyumen/full/` — ранний неполный прогон через Overpass;
   в нём нет полного набора итоговых таблиц. Ноутбуки его не используют.
4. `examples/data_tyumen/test/` — тестовый прогон; к итоговому исследованию
   не относится.
5. `examples/tyumen_pipeline.ipynb` — ранняя неполная версия ноутбука;
   основной первоначальный результат сохранён в `original/`.
6. `examples/data_tyumen_pbf/full/` — исходный прогон, из которого сделана
   копия `original/`; он также не изменялся.
7. `examples/data_tyumen_pbf/full_fixed/` — более ранний исправленный прогон
   **без** дополнительного split крупных кварталов. Ноутбуки не читают его
   напрямую. Из него в `refined/` скопированы только исходные слои
   `buildings_raw`, `schools_raw`, `water` и `railways`; его кварталы, матрица
   и итоговые таблицы не используются.
8. Матрицы доступности большие (сотни мегабайт). Не коммитьте их в Git без
   Git LFS.

## Порядок запуска refined

1. Откройте `examples/tyumen_pipeline_refined.ipynb` в VS Code.
2. Выберите ядро `.venv-blocksnet`.
3. Выполните `Kernel → Restart Kernel and Run All Cells` или идите по ячейкам
   сверху вниз.
4. Матрица доступности считается порциями и переживает остановку: готовые
   порции лежат в `refined/accessibility_matrix_parts/`. Если ОЗУ мало,
   закройте лишние программы и запустите ячейку матрицы ещё раз. На малой ОЗУ
   ноутбук автоматически переходит на порцию 25 строк и один поток.
   Если матрица всё же остановилась из-за памяти, перезапустите ядро и
   выполните только ячейки «Импорты и настройки», «Вспомогательные функции»
   и «Матрица доступности»: она сама загрузит `blocks_land_use.geojson` и
   `graph.pkl`, а готовые порции продолжит использовать.
5. После расчёта проверьте раздел 11 и сравнение в разделе 12.
6. Если карты в основном ноутбуке не строятся из-за старой вкладки VS Code,
   откройте `examples/tyumen_final_maps.ipynb` и выполните `Run All`. Он не
   пересчитывает данные: читает готовые `results_table.csv` и кварталы,
   строит карты и сохраняет `refined/comparison_maps.png`.
7. Ноутбук `tyumen_pipeline_original.ipynb` можно открыть отдельно для
   просмотра baseline; его данные уже посчитаны.

## Dashboard

Отдельный скрипт `examples/tyumen_dashboard.py` собирает один
`examples/data_tyumen/dashboard.html` из готовых файлов:

- интерактивная карта кварталов (original/refined, школы, вода, граница)
  с переключателем цвета: население, обеспеченность, доступность,
  FSI/GSI/MXI/L/OSR, ёмкость школ и жилая площадь;
- графики по населению, доступности, землепользованию и морфотипам;
- таблицы comparison.csv, results_summary.csv, provision_schools.csv,
  кластеров Spacematrix, распределений морфотипов, blocks_quality.json,
  matrix_meta.json, всех числовых показателей и проверок качества;
- выводы и ограничения.

Скрипт не скачивает данные, не использует Overpass и не пересчитывает матрицу
или метрики. Запуск из корня репозитория:

```powershell
.\.venv-blocksnet\Scripts\python.exe .\examples\tyumen_dashboard.py
```

После выполнения откройте `examples/data_tyumen/dashboard.html` в браузере.

## Финальная версия страницы

Файл для сдачи — `examples/data_tyumen/dashboard_refined.html`.
Он собирается скриптом `examples/tyumen_dashboard_refined.py` и использует
**только refined-данные**: refined-кварталы, refined-показатели, refined-школы,
воду и границу. В интерфейсе нет слоёв, карт и таблиц сравнения с прежней
нарезкой.

Структура страницы:

- «Методика исследования» — как получены данные, какие величины являются
  модельными оценками и как уточнялась квартальная структура;
- «Ключевые показатели» — сводные числа по территории;
- «Интерактивная карта Тюмени» — одна карта Leaflet с переключателем
  показателей; слева карта, справа легенда, список слоёв и график
  выбранного показателя; карта, легенда и график обновляются одновременно;
- «Градостроительные показатели» — определения всех показателей;
- «Дополнительная аналитика» — графики, которые не относятся к одному
  квартальному показателю;
- «Сводная статистика», «Все числовые показатели», рейтинги кварталов,
  школьная сеть, категориальные распределения, портреты кластеров
  Spacematrix, «Соответствие исходному заданию», проверки качества,
  выводы, ограничения и источники.

Пересобрать финальный HTML из корня репозитория:

```powershell
.\.venv-blocksnet\Scripts\python.exe .\examples\tyumen_dashboard_refined.py
```

Открыть результат:

```powershell
Start-Process ".\examples\data_tyumen\dashboard_refined.html"
```

Скрипт не скачивает данные, не использует Overpass и не пересчитывает матрицу
доступности. Предыдущие `dashboard.html` и `dashboard_final.html` не
перезаписываются.
